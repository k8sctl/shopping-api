# ADR-001: 이미지 태그 전략

## 상태
결정됨

## 배경
Docker 이미지를 빌드하고 레지스트리에 푸시할 때 어떤 태그 전략을 사용할지 결정이 필요했습니다. 태그 전략에 따라 버전 추적, 롤백, CI/CD 파이프라인 구성 방식이 달라집니다.

## 고려한 옵션

**1. latest 태그**
```
k8sctl/shopping-api:latest
```
- 장점: 단순함
- 단점: 어떤 버전인지 알 수 없음, 롤백 시 이전 버전 특정 불가, CI/CD 캐시 문제 발생

**2. 버전 태그 (SemVer)**
```
k8sctl/shopping-api:1.0.0
k8sctl/shopping-api:1.0.1
```
- 장점: 명확한 버전 관리, 롤백 용이
- 단점: 버전 수동 관리 필요

**3. Git 커밋 해시**
```
k8sctl/shopping-api:a1b2c3d
```
- 장점: 어떤 코드로 빌드됐는지 추적 가능, 자동화 용이
- 단점: 버전 의미가 직관적이지 않음

**4. 날짜 + 커밋**
```
k8sctl/shopping-api:20260607-a1b2c3d
```
- 장점: 언제 빌드됐는지 + 코드 추적 가능
- 단점: 태그가 길어짐

## 결정
**버전 태그 (SemVer) 사용**

```
k8sctl/shopping-api:1.0.0
```

## 이유
- 명확한 버전 의미 전달 (1.0.0 = 메이저.마이너.패치)
- 롤백 시 특정 버전으로 명확하게 되돌릴 수 있음
- Kubernetes Deployment에서 버전 추적 용이
- 팀원과 버전 소통이 직관적

## 트레이드오프
- 버전 번호를 수동으로 관리해야 함
- CI/CD 파이프라인에서 자동 버전 증가 로직 필요

## 향후 계획
CI/CD 파이프라인 구축 시:
```
Git 태그 → 자동으로 이미지 태그 생성
git tag v1.0.1
→ GitHub Actions → k8sctl/shopping-api:1.0.1 자동 빌드/푸시
```
